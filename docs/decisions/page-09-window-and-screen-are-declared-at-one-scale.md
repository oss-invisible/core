# page-09: window and screen are declared, at one scale

**Rule.** The window geometry a page reads comes from the declaration in every window state and on every host. It never comes from the host's window manager.
- Outer size, `screenX`, `screenY`, the content origin and mouse events follow the declared frame. The declared fullscreen is the screen: outer, inner and screen are equal and the position is 0. This holds on an X display with no window manager too.
- The core declares the screen in `zoom.stealth.screen.*`: size and depth in CSS pixels, the work area and the window frame in device pixels, and `zoom.stealth.screen.taskbar_px`. The available height is the declared height minus the taskbar. The device-size and pointer media queries answer from the declared prefs (the pointer ones are derived from the touch point count).
- The scale is the `screen.dpr` of the persona. The profile writes `layout.css.devPixelsPerPx` and `ui.textScaleFactor` in every session.
- The core accepts the display scales Windows offers: the 12 entries of the Settings table, 100 to 500% (`WINDOWS_SCALE_PERCENTS`). A scale is accepted only if Windows offers it for the declared screen, i.e. if the effective resolution stays at least 800x600. Any other scale is refused.
- At every accepted scale the window frame is computed by formula from its sources, never typed per scale:
  - the resize border and the caption come from the Windows metrics;
  - the popup toolbar and the main-window bar come from Firefox's CSS with its app-unit rounding.
- A seed samples only the scales of the persona pool (`FRAME_SCALES`), with their frequencies.
- There is one scale for the whole geometry: the screen width times the scale equals the work area width in device pixels, within 1 px. Otherwise the engine refuses the declaration.
- `screenX` minus `clientX` equals `mozInnerScreenX`, and the same holds on Y.
- `inRDMPane` is true only when `zoom.stealth.screen.width` is not active, and false again when the viewport returns to the real one.
- Window state does not depend on the desktop. In every session the core declares `zoom.stealth.widget.occlusion_tracking.enabled` and the Windows pref of the same meaning as `False`, from one value, and `zoom.stealth.focus.ignore_os_deactivation` as `True`: the focus a page reads follows the session, not the desktop. With a visible window, `document.hidden` is `false` and `visibilityState` is `"visible"`, and `enumerateDevices()` resolves.
- A window fully covered by another one is not treated as hidden. A retail browser with the occlusion tracker on would become hidden in that case. This is a declared difference, and no other occlusion episode is.
- The BFCache stays enabled on every host. Back and forward navigation behave as in a user's browser.

**Enforced by.** `tests/test_prefs.py::test_the_window_frame_is_declared_in_device_pixels_per_scale` fails when the frame, the work area or the viewport of a scale is not the declared one. `tests/test_prefs.py::test_a_scale_windows_does_not_offer_is_refused` and `tests/test_window_frame_formulas.py::test_a_scale_the_screen_does_not_offer_is_refused` fail when a scale Windows does not offer, or does not offer for that screen, is accepted. `tests/test_window_frame_formulas.py` fails when a frame value differs from its formula or from retail's measurements (rounds 4-7), including `::test_every_accepted_scale_has_the_frame_from_the_formulas` and `::test_the_bar_is_the_retail_offset_of_the_browser_element_rounded_once`. `tests/test_profile_coherence.py::test_availheight_matches_the_taskbar_with_no_pin_at_all` and `::test_a_pinned_taskbar_moves_availheight` fail when the available height and the taskbar disagree. `tests/test_screen_dpr_pool.py::test_every_sampled_scale_has_its_frame_and_prefs` fails when a sampled scale has no frame or no prefs. `tests/test_headless.py::test_occlusion_tracking_is_off_for_every_session` and `::test_occlusion_is_one_decision_for_both_engines` fail when occlusion tracking is on or the two engine names disagree. `tests/test_headless.py::test_the_focus_follows_the_session_not_the_desktop` fails when `zoom.stealth.focus.ignore_os_deactivation` is not declared. `firefox_antidetect_patch: fingerprint/screen-window/geometry/src/dom/events/test/gtest/TestStealthWindowGeometry.cpp` and `firefox_antidetect_patch: fingerprint/screen-window/geometry/src/widget/tests/gtest/TestStealthFullscreen.cpp` fail when the window geometry or the fullscreen state does not follow the declaration. `firefox_antidetect_patch: platform/declaration-gate/src/gfx/thebes/gtest/TestStealthScaleDeclaration.cpp` fails when the engine accepts a scale other than the declared one.

**Why.** The geometry of the host must not appear on the page. The declared value stays the profile's even when the host changes its scale or accessibility settings. Screen in CSS pixels, work area and frame live on different scales, so one scale must tie them. A frame value typed per scale would be right only where it was measured; a formula from its source is right at every scale Windows offers, and the measurements are its tests. A covered window that reads as hidden throttles timers and `requestAnimationFrame`, freezes video and leaves `enumerateDevices()` pending, and a retail user's browser does not do that. The window signals must not depend on the state of the desktop.

**Files.** `src/invisible_core/prefs.py` (`_apply_screen`, the occlusion and focus block of `compose_session_prefs`), `src/invisible_core/window_frame.py` (the formulas, their source integers and the accepted scales), `src/invisible_core/constants.py` (`WINDOW_FRAME_BY_DPR` built from the formulas, `TASKBAR_PX`), `src/invisible_core/_fpforge/profile.py` (`ScreenProfile`), `firefox_antidetect_patch: fingerprint/screen-window/geometry/FEATURE.md`, `firefox_antidetect_patch: fingerprint/screen-window/screen/FEATURE.md`, `firefox_antidetect_patch: fingerprint/screen-window/css-media/FEATURE.md`, `firefox_antidetect_patch: fingerprint/screen-window/focus/FEATURE.md`, `firefox_antidetect_patch: fingerprint/screen-window/occlusion/FEATURE.md`, `firefox_antidetect_patch: platform/declaration-gate/FEATURE.md`, `firefox_antidetect_patch: automation/juggler/src/juggler/TargetRegistry.js`.

**Don't.**
- Take the geometry from the window manager, or use different scales in different parts of the geometry.
- Use an engine constant for the taskbar, or turn RDM on while a screen is declared.
- Turn the BFCache off for the driver's convenience, or add a pref that turns it off.
- Rename the `zoom.stealth.*` or `stealthfox.*` prefs, or tie them to a condition of the desktop.
